# NIBSS by Phoenix — API Backend & Fintech Portal
**Built for Assignment 2 | TS Academy Phoenix Cohort**

This project is a complete backend simulator for the Nigerian Interbank Settlement System (NIBSS). It includes a fully functional REST API, a MongoDB database architecture, and a lightweight web-based Fintech Portal (UI) to interact with the API.

---

## 🚀 Features Implemented
* **Fintech Onboarding & Auth:** API key generation, automated bank code assignment, and JWT-based route protection.
* **Identity Management:** Centralized BVN and NIN registration and validation (Public Routes as per live API specs).
* **Account Engine:** Creation of NUBAN accounts strictly tied to validated BVN/NIN identities.
* **Ledger / Transactions:** Secure interbank transfers with strict sender-ownership checks and atomic balance updates.
* **Fintech UI Portal:** A clean, vanilla HTML/JS frontend hosted by the Node server to visualize accounts and execute transfers.
* **Automated Integration Testing:** A complete bash script that sequentially tests all 12 endpoints.

## 🛠️ Project Setup for Reviewers

To run and review this project locally, please follow these steps.

### 1. Prerequisites
* Node.js installed on your machine.
* A MongoDB connection string (either a local instance on port `27017` or a MongoDB Atlas cluster URI).

### 2. Installation
Clone the repository and install the dependencies:
```bash
npm install
```

### 3. Environment Variables
Create a `.env` file in the root directory. You must provide your own MongoDB URI to test the database features:
```env
MONGO_URI=mongodb+srv://<your_user>:<your_password>@cluster0.xxxxx.mongodb.net/nibss_phoenix
PORT=3000
JWT_SECRET=super_secret_jwt_key_123
```

### 4. Start the Server
Run the development server:
```bash
npm run dev
```
You should see:
```
🚀 Server running on http://localhost:3000
✅ MongoDB Connected: <your-cluster-url>
```

## 🧪 How to Test the API & UI

### Method A: The Automated Test Script (Recommended)
We have included an automated bash script that sequentially hits every endpoint, extracts keys, handles JWTs, and creates accounts. 
Open a **second terminal window** and run:
```bash
chmod +x test.sh
./test.sh
```
**Important:** Look at the output under `[1] POST /api/fintech/onboard`. **Copy the `apiKey` and `apiSecret`**. You will need them for the UI!

### Method B: The Web UI (Fintech Portal)
1. After running the test script (to generate your API keys and accounts), open your browser to **[http://localhost:3000](http://localhost:3000)**.
2. Paste the `apiKey` and `apiSecret` generated by the test script into the login form.
3. Once logged in, you will see the Dashboard where you can:
   * View all customer accounts linked to your Fintech.
   * Create a new account using BVN or NIN (Use BVN `10840712847` / DOB `2000-05-15`).
   * Perform an Interbank Transfer (watch the balances update in real-time).

## 🔐 Security & Best Practices Implemented
* **Ownership Checks:** The `POST /api/transfer` endpoint uses the JWT payload to verify the sender account *actually belongs* to the authenticated Fintech. A Fintech cannot guess another bank's account number to steal funds.
* **Denormalization:** The `Account` model stores both `fintechId` (for secure ownership queries) and `bankCode` (for instant interbank routing logic).
* **Data Validation:** Strict regex is used on identity endpoints to enforce 11-digit BVN/NIN formats.
* **Separation of Concerns:** The code is cleanly divided into Routes, Controllers, Models, and Middleware, making it highly maintainable.
